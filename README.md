## 🧠 Architectural Overview

Traditional agentic workflows throw a massive context file at an LLM and pray for a functional monolithic output. This causes severe attention degradation and critical security failures. 

**L.Y.A.A.D.** solves this by acting as a **Hierarchical Local Orchestrator**. It ingests a single markdown context specification and partitions it into completely isolated, sandboxed **Micro-Departments**. Each subfolder functions as an autonomous microtask, governed by mathematical evaluation gates and isolated validation tests before it can touch the main codebase pipeline.

### The Decoupled Engine Flow

* **The Single Source of Truth (`lyadd.context.md`):** Your product specification, features, and core requirements go here.
* **The Parser Engine (`orchestrator.py`):** A memory-optimized, local pipeline built specifically to run on consumer hardware (tested on an **HP Victus 8GB RAM setup**). It dynamically slices the master context into compartmentalized modules.
* **Micro-Departments:** Independent sub-directories containing an explicit markdown instruction header, an evaluation metric ruleset (`evaluation.json`), the sub-agent output (`implementation.py`), and a distinct execution matrix (`test_report.json`).
* **The Strict Gatekeeper Framework (`gatekeeper.py`):** An automated parser that scans the metrics of every micro-department. It halts the final build pipeline if any subtask fails static code analysis or breaches performance metrics.

## ⚡ 8GB RAM Hardware Optimization Matrix

Unlike heavy enterprise frameworks that require expensive cloud compute resources or dual-GPU rigs, L.Y.A.A.D. is meticulously engineered for the everyday local developer machine. The entire testing suite and orchestration execution map have been baseline-tested on an **HP Victus (fa1xxx) featuring 8GB RAM**.

### How We Optimize Local Inference:
* **Quantized Local Models:** Specifically architected to lean on lightweight, high-performance open-source models like **Qwen-2.5-Coder-7B-Instruct (Q4_K_M quantization via Ollama)**.
* **Zero-Leak Processing:** The Python orchestration loop leverages streamed context passing, ensuring your host memory pressure stays below **4.2 GB** during local evaluation sweeps.
* **Decoupled Evaluation Gates:** Tests are run in sequential, isolated sub-processes rather than concurrent parallel routines, preventing memory thrashing and keeping your system snappy.

## Getting Started

### 1. Prerequisites
Ensure you have Python 3.10+ installed and [Ollama](https://ollama.com) running in the background.

```bash
# Pull the optimized coding engine model
ollama pull qwen2.5-coder:7b
```

### 2. Run the Initialization Pipeline
Clone the repository, drop your product specs into `lyadd.context.md`, and execute the structural orchestrator:

```bash
python orchestrator.py
```

### 3. Trigger the Validation Gatekeeper
Once your sub-agents complete their localized tasks, verify the integrity of the build:

```bash
python gatekeeper.py
```
